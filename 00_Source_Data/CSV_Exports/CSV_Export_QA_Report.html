تفاصيل الفحوصات

  • Encoding: كل ملف بيبدأ بـ BOM واحد بس، والـ decoding بـ utf-8-sig strict نجح من غير أي خطأ. مفيش NUL bytes. نهاية السطور LF.
  • Parsing: قريت كل ملف بـ csv.reader(strict=True)، وبعدين عملت re-serialize بـ QUOTE_ALL — الناتج طابق الملف الأصلي byte-by-byte في الـ 14 ملف. ده بيثبت إن كل field بين علامات تنصيص والـ quotes متضاعفة صح، ومفيش صف اتبلع أو اتقطع.
  • NULL vs empty string: الـ NULL مكتوب \N. مفيش ولا خلية فاضية ("") في أي ملف، وعدد الـ \N في كل عمود طابق عدد الـ NULL في SQL بالظبط. ومفيش أي نص حقيقي في البيانات بيساوي NA أو NULL أو None.
  • التواريخ: كل أعمدة الـ date بصيغة YYYY-MM-DD (100%). الـ timestamps بصيغة YYYY-MM-DDTHH:MM:SS من غير كسور ثواني — واتأكدت إن الكسور في SQL كلها صفر، يعني مفيش precision ضاع.
  • Decimals: مكتوبة نص بنفس الـ scale بتاع SQL (مثلاً decimal(18,2) → دايماً رقمين عشريين، decimal(18,3) → 3). مفيش float rounding.
  • IDs و Barcode: محفوظة نص بالظبط زي SQL (اتقارنت قيمة بقيمة). الـ Barcode موجود في 8 منتجات بس من 227.
  • Truncation: مفيش — المقارنة الكاملة للنصوص (Description, StockItemName ...) طابقت SQL.
  • ملاحظة صغيرة: PackageTypeName فيه قيمة 'Tub ' بمسافة في الآخر — دي قيمة المصدر نفسه، مش خطأ تصدير.

الاختبارات اللي اتعملت

  1. التأكد إن الـ 14 جدول موجودين، وقراءة كل الأعمدة من sys.columns (النوع، الـ precision/scale، NULL، computed، temporal).
  2. الـ PK والـ FK من sys.indexes و sys.foreign_keys.
  3. COUNT(*) لكل جدول مقابل عدد صفوف الـ CSV.
  4. أسماء الأعمدة وترتيبها مقابل ترتيب SQL.
  5. مقارنة كاملة خلية بخلية: سحبت كل صفوف كل جدول (الأعمدة المصدَّرة) مرتبة بالـ PK، وحولت كل قيمة لنص بصيغة ثابتة (int/bit/decimal بـ CAST، date بـ style 23، datetime2 بـ style 121)، وقارنتها بالـ CSV بعد قراءته بالـ options الموثقة — بما فيها الـ NULL.

  • Invoices → InvoiceLines: 1:N (1 لـ 5، متوسط 3.24). ومفيش منتج متكرر في نفس الفاتورة.

  • مورد أمر الشراء = مورد المنتج في كتالوج StockItems في 100% من السطور.

مخاطر الـ Join ببساطة

Row multiplication: لو عملت join بين OrderLines و Invoices و InvoiceLines عن طريق OrderID، كل سطر أمر هيتكرر مع كل سطر فاتورة لنفس الأمر → النتيجة 847,091 صف بدل 231,412. لو جمعت الكميات بعدها، هتطلع أرقام مضروبة ×3 تقريباً. الحل: اعمل aggregate لكل جدول على المستوى المطلوب الأول (مثلاً لكل OrderID) وبعدين اعمل join.
  • Header totals: متجمعش TotalDryItems بعد ما تعمل join مع سطور الفاتورة — هيتكرر مع كل سطر.
  • Lines → Header: join من السطور للرأس يكون many-to-one؛ استخدم validate='many_to_one' في merge() واتأكد إن عدد الصفوف ماتغيرش.
  • نوع البيانات في المفاتيح: لازم يكون نفس الـ dtype في الناحيتين (string مع string) وإلا الـ merge هيفشل أو يطلع فاضي.
  • Units vs Outers: متجمعش OrderedOuters مع كميات المبيعات؛ حوّل الأول بـ QuantityPerOuter.
  • StockGroups (لو اتضافت): Many-to-Many → المنتج الواحد ممكن يتحسب في فئتين.
